# Internationalization (العربية / English)

## الجاهز الآن

- كل الصفحات تحت `app/[locale]`، و `lang`/`dir` يُحددان من `lib/i18n/config.ts`.
- العربية (`ar`, RTL) بدون بادئة في الرابط؛ أي لغة أخرى ببادئة (`/en/...`).
- نصوص الواجهة كاملة بالعربية والإنجليزية (`dictionaries/ar.ts`, `dictionaries/en.ts`)، والنوع `Dictionary` يجبر الترجمة على اكتمال كل المفاتيح.
- التصميم بالخصائص المنطقية (`ms/me/ps/pe/start/end`) فيعمل في الاتجاهين بلا تعديل.
- `buildPageMetadata` يضيف `hreflang` تلقائياً، و `sitemap.ts` يضيف الـ alternates، عند وجود أكثر من لغة.
- التواريخ والأرقام عبر `Intl` حسب اللغة (أرقام لاتينية للعربية).

## الإنجليزية معطلة حالياً — لماذا؟

المحتوى القادم من الـ API (المشاريع، الفريق…) بلغة واحدة. تفعيل الإنجليزية الآن يعرض واجهة إنجليزية بمحتوى عربي. تُفعَّل عند ترجمة المحتوى.

## خطوات تفعيل الإنجليزية

### 1. المحتوى في الـ backend

الأسلوب المقترح: جداول ترجمة لكل نوع محتوى، مع إبقاء الحقول غير النصية في الجدول الأصلي:

```prisma
model ProjectTranslation {
  projectId      Int
  locale         String  @db.VarChar(5)
  title          String  @db.VarChar(160)
  summary        String  @db.VarChar(400)
  description    String? @db.Text
  // … باقي الحقول النصية
  project Project @relation(fields: [projectId], references: [id], onDelete: Cascade)
  @@id([projectId, locale])
}
```

- الـ endpoints العامة تقبل `?locale=en` (مع fallback للعربية إن لم توجد ترجمة).
- لوحة التحكم: تبويب لكل لغة في نماذج المحتوى.

### 2. الموقع

1. أضف `'en'` إلى `enabledLocales` في `lib/i18n/config.ts`.
2. مرر `locale` إلى دوال `lib/api/content.ts` وأضفه إلى الطلب (والـ cache key تلقائياً عبر الرابط).
3. أضف مبدّل لغة في الـ Header يستخدم `localizePath(currentPath, otherLocale)`.
4. `npm run build` — ستُولَّد `/en/...` تلقائياً عبر `generateStaticParams`.

لا تغييرات مطلوبة في الـ layout أو التصميم أو التوجيه.
